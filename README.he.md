# Task Runner מודולרי ב-Node.js

כלי שורת פקודה (CLI) גמיש וחזק לאוטומציה של משימות חוזרות בתהליכי פיתוח. הכלי מאפשר להגדיר, לנהל ולהריץ רצף של פעולות (כמו יצירת קבצים, הרצת פקודות וביצוע פעולות Git) באמצעות קובץ תצורה מרכזי, פשוט וקריא בפורמט JSON.

הכלי נבנה עם דגש על מודולריות, קלות הרחבה, וחווית משתמש נוחה, כולל אשף אינטראקטיבי להרצה מבוקרת.

## תכונות עיקריות

*   **ארכיטקטורה מודולרית:** כל משימה היא "קופסה שחורה" בתיקייה משלה, עם הקוד והנכסים שהיא צריכה.
*   **תצורה הצהרתית (`config.json`):** הגדר את "מה" אתה רוצה שיקרה, וה-Runner ידאג ל"איך". קל לקריאה ולתחזוקה.
*   **אשף אינטראקטיבי (Wizard):** הרץ את המשימות צעד אחר צעד ואשר כל פעולה, או דלג על האשף להרצה אוטומטית מלאה.
*   **משתנים דינמיים:** השתמש בערכים מקובץ התצורה (כמו שם הפרויקט) כדי ליצור נתיבים ותכנים דינמיים.
*   **אינטגרציית Git מובנית:** בצע פעולות `add`, `commit` ו-`push` באופן אוטומטי לאחר הצלחה של כל משימה.
*   **הרחבה פשוטה:** הוספת יכולות חדשות מסתכמת בהעתקת דוגמה, שינוי קל, ועדכון קובץ התצורה.
*   **לוגים מפורטים:** לוגים צבעוניים בקונסול וכתיבה לקובץ לטובת ניתוח ותיעוד.

## מבנה הפרויקט

```
/
├── index.js              # הסקריפט הראשי שמריץ את התהליך
├── config.json           # קובץ התצורה המרכזי - כאן מגדירים הכל
├── logger.js             # הגדרות מערכת הלוגים (Winston)
├── git-handler.js        # מודול ייעודי לטיפול בפעולות Git
├── package.json          # תלויות הפרויקט
│
├── tasks/                # תיקייה המכילה את כל המשימות בפרויקט
│   └── <action-name>/
│       ├── index.js      # הלוגיקה של המשימה
│       └── (assets...)   # קבצים נוספים שהמשימה צריכה (תבניות, תמונות וכו')
│
├── examples/             # אוסף דוגמאות מוכנות לשימוש עבור משימות נפוצות
│
└── utils/                # כלי עזר משותפים, כמו פותר התבניות
    └── template-resolver.js
```

## התקנה והגדרה ראשונית

### דרישות קדם

הדרישה היחידה להרצת הכלי היא התקנה של Node.js:

*   **Node.js:** `^20.19.0`

### שלבי התקנה

1.  **שכפול הפרויקט:**
    ```bash
    git clone https://github.com/ShaiGerbi/GenBoil
    cd GenBoil
    ```

2.  **התקנת תלויות:**
    ```bash
    npm install
    ```

3.  **הגדרת `config.json`:**
    זהו השלב החשוב ביותר. פתח את הקובץ `config.json` והתאם אותו לפרויקט שלך. הנה דוגמה בסיסית להתחלה:
    ```json
    {
      "project": {
        "name": "MyAwesomeApp",
        "description": "אפליקציה מדהימה",
        "basePath": "C:/Projects/MyAwesomeApp",
        "version": "1.0.0"
      },
      "settings": {
        "logLevel": "info",
        "logFile": "./runner.log"
      },
      "tasks": [
        {
          "action": "create-readme",
          "description": "יוצר קובץ README ראשוני",
          "enabled": true,
          "params": {
            "destFile": "./README.md",
            "content": "# ${project.name}\n\n${project.description}"
          },
          "git": {
            "add": ["./README.md"],
            "commit": "Initial commit: Create README.md",
            "push": false
          }
        }
      ]
    }
    ```

## אופן השימוש

### הרצה אינטראקטיבית (עם אשף)

הדרך המומלצת להרצה ידנית. הכלי ישאל אותך לפני ביצוע כל משימה.
```bash
node index.js
# או בקיצור
npm start
```
**פלט לדוגמה:**
`? Run task 'create-readme' (יוצר קובץ README ראשוני)? › (Y/n)`

### הרצה אוטומטית (ללא אשף)

מושלם לשימוש בסקריפטים או בתהליכי CI/CD. השתמש בדגל `--yes` או `-y`.
```bash
node index.js --yes
```

### הרצת משימות ספציפיות

ניתן להריץ רק חלק מהמשימות שהוגדרו בקונפיגורציה באמצעות הדגל `--tasks` או `-t`, עם רשימה מופרדת בפסיקים של שמות הפעולות.
```bash
# הרצת משימה בודדת
node index.js --tasks=create-readme

# הרצת מספר משימות
node index.js --tasks=create-readme,build-project
```

## קובץ התצורה `config.json`

הקובץ מחולק לשלושה חלקים עיקריים:

### 1. `project`
אובייקט המכיל מידע כללי על הפרויקט שלך. ניתן להשתמש בערכים אלו כמשתנים דינמיים בשאר הקובץ.
*   `name`: שם הפרויקט.
*   `basePath`: נתיב הבסיס של הפרויקט שלך. **כל הנתיבים היחסיים במשימות יחושבו ביחס לנתיב זה.**
*   `version`: גרסת הפרויקט.

### 2. `settings`
הגדרות פנימיות של ה-Runner.

*   `logLevel`: קובע את רמת הפירוט של הלוגים שיוצגו בקונסול. קביעת רמה מסוימת תציג את כל ההודעות ברמה זו וברמות שמעליה (החמורות יותר).
    הרמות האפשריות, מהמפורטת ביותר לחמורה ביותר, הן:
    *   `debug`: כל המידע, כולל הודעות מפורטות לניפוי שגיאות.
    *   `success`: הודעות הצלחה מיוחדות (למשל, סיום מוצלח של משימה).
    *   `info`: (ברירת מחדל) מידע כללי על התקדמות התהליך והרצת המשימות.
    *   `warn`: אזהרות על בעיות פוטנציאליות שלא עצרו את הריצה.
    *   `error`: רק שגיאות קריטיות שעצרו את הריצה או דורשות תשומת לב.
*   `logFile`: נתיב לקובץ הלוגים שייווצר.

### 3. `tasks`
מערך של אובייקטים, כאשר כל אובייקט מייצג משימה לביצוע. **הסדר במערך קובע את סדר הריצה.**

**מבנה אובייקט משימה:**
*   `action` (חובה, מחרוזת): שם הפעולה לביצוע. חייב להיות זהה לשם התיקייה של המשימה בתיקיית `tasks`.
*   `description` (אופציונלי, מחרוזת): תיאור ידידותי למשתמש שיוצג באשף.
*   `enabled` (אופציונלי, בוליאני): קבע `false` כדי לדלג על משימה זו באופן זמני. אם השדה חסר, המשימה נחשבת פעילה (`true`).
*   `params` (חובה, אובייקט): אובייקט המכיל את הפרמטרים הספציפיים שהמשימה צריכה כדי לעבוד.
*   `git` (אופציונלי, אובייקט): הגדרות לביצוע פעולות Git **לאחר שהמשימה הסתיימה בהצלחה**.

## יכולות מתקדמות

### משתנים דינמיים
ניתן להשתמש בכל ערך מתוך אובייקט ה-`config` כמשתנה דינמי בתוך מחרוזות. השתמש בתחביר `${path.to.value}`.
ה-Runner יחליף אוטומטית את המשתנים בערכים המתאימים לפני הרצת המשימה.

**דוגמה:**
המחרוזת `"./src/${project.name}/main.js"` תהפוך ל-`"./src/MyAwesomeApp/main.js"`.

### פעולות Git אוטומטיות
הוספת אובייקט `git` למשימה תפעיל פעולות Git מבוקרות לאחר שהמשימה הצליחה.

**מבנה אובייקט `git`:**
*   `add` (אופציונלי, מחרוזת או מערך): נתיב בודד או רשימת נתיבים להוספה (`git add`).
*   `commit` (אופציונלי, מחרוזת או בוליאני):
    *   **כמחרוזת:** הודעת ה-commit שתשמש (`git commit -m "..."`).
    *   **כ-`true`:** **חכם!** ישתמש בערך של שדה ה-`description` של המשימה כהודעת ה-commit.
*   `push` (אופציונלי, בוליאני): אם `true`, יבצע `git push` לאחר ה-commit.

## איך להוסיף משימה חדשה

הדרך הקלה ביותר היא להשתמש בדוגמאות המוכנות מתיקיית `examples`.

1.  **בחר דוגמה:** עיין בתיקיית `examples` ומצא את קובץ הדוגמה שהכי מתאים לצרכים שלך (למשל, `create-file.js`).

2.  **צור תיקייה והעתק:** צור תיקייה חדשה בתוך תיקיית `tasks` ותן לה שם משמעותי שמתאר את הפעולה (למשל, `create-main-activity`). לאחר מכן, העתק את קובץ הדוגמה שבחרת לתוך התיקייה החדשה.

3.  **שנה את שם הקובץ:** בתוך התיקייה החדשה, **שנה את שם קובץ הדוגמה שהעתקת ל-`index.js`**. זהו שלב חיוני.

4.  **(אופציונלי) הוסף נכסים:** אם המשימה שלך צריכה קבצי תבנית או נכסים אחרים, הנח אותם בתוך תיקיית המשימה שיצרת.

5.  **עדכן את `config.json`:** הוסף אובייקט משימה חדש למערך `tasks`. השתמש בשם התיקייה שיצרת בתור הערך של `action`, והגדר את הפרמטרים הנדרשים.

6.  **הרץ!** הכלי יזהה את המשימה החדשה ויוסיף אותה לתהליך.
